# 参考方法与工具取舍

查阅日期2026-10-20。以下为方法来源和潜在集成选项，不代表背书、认证或已安装依赖。DeliveryOS的代码、文字和模板为原创，没有打包外部框架代码。

| 参考 | 采用内容 | 边界 |
|---|---|---|
| [GOV.UK交付指南](https://www.gov.uk/service-manual/agile-delivery) | 先理解问题，验证高风险假设，再逐步交付 | 不照搬政府审批或典型时长 |
| [GAO成本估算指南](https://www.gao.gov/products/gao-20-195g) | 技术基线、工作分解、证据、假设、风险和实际成本反馈 | 方法不为某个项目数字背书 |
| [arc42](https://arc42.org/overview/) | 检查架构边界、约束、运行、部署、决策和质量 | 按需参考，未复制模板 |
| [GitHub Spec Kit](https://github.com/github/spec-kit) | 后续可选的需求到任务及代码执行流程 | 本身不覆盖商务与现场交付全过程 |
| [BMad Method](https://github.com/bmad-code-org/BMAD-METHOD) | 产品、架构、体验、开发和测试视角 | 先作方法参考，不默认叠加两套主流程 |
| [Promptfoo](https://github.com/promptfoo/promptfoo) | 模型、提示词和知识问答的自动回归候选 | 有AI评估需要时采用，不代替业务验收 |
| [OpenAI Skills](https://developers.openai.com/plugins/concepts/skills) | 可携带的指引、按需参考、脚本和模板 | 助手仍需相应工具、权限和复核 |

Spec Kit、BMad和Promptfoo仓库标示MIT；arc42文档与模板标示CC BY-SA 4.0，其[许可说明](https://github.com/arc42/arc42-template/blob/main/LICENSE.txt)区分改编模板与用户自有内容。后续复制外部代码或模板时核对固定版本及附加条款，保留适用声明。模型权重、数据和服务可能另有许可。

流程也吸收了已脱敏的实践观察：来源权威混淆、提交要求遗漏、技术假设未验证、容量推人天和验收状态混用。未包含客户名称、原件或声称已完成项目的业绩。
