# Technical approach

Working template; no project facts have been established.

## Recommendation and alternatives

Recommend a feasible approach and explain conditions, evidence and unresolved assumptions. Screen hard constraints before comparing build, buy and reuse. No fixed number of alternatives unless requested.

## Boundary and runtime

Show existing and new systems, actors, data flows and deployment. Trace a real request. Explain AI, deterministic code and human responsibilities, and why each module is needed.

## Integration and operation

Address authorization, audit, queues, capacity, failures, backup/restore, maintenance, cost and exit. Distinguish measured results from vendor claims and extrapolation.

## Risk-reducing experiments

Test assumptions that could change the decision. Specify fixed inputs, versions, environment, success criteria, budget and stopping condition. Preserve raw results and failures. Avoid repeating unchanged failed runs.
