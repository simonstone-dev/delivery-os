# Business and requirements

Working template; no project facts have been established.

## Submission checklist

Map mandatory, optional and later deliverables, deadlines and missing items. Cover technical proposal, schedule, effort or price, actual team, site work and support as required.

## Journeys, rules and data

Document normal, boundary, exception and correction cases. Identify stable IDs, units, states, effective dates and versions. Check spreadsheet formulas and external links instead of trusting them.

## Interfaces and ownership

List specific read, reserve, write and rollback capabilities, permissions, test environment, limits, costs and vendor responsibilities. An API's existence does not prove every capability.

## Traceability and acceptance

Maintain source → requirement → work package → acceptance → evidence links in registers.json. Define dataset, scale, environment, timing, denominator, threshold, infeasible cases and approval authority. Track conflicts as questions.
